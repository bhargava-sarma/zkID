# @zkid/issuer-registry

The issuer keys a zkID verifier trusts, each for one credential (`document`):
UIDAI's Secure QR signing keys (`aadhaar`) and DigiLocker's document-signing
key (`pan`, for PAN Verification Records). Each key is stored as the key hash
its credential's circuit outputs (`pubkeyHash`: Anon Aadhaar's Poseidon hash
for a QR, the PAN circuit's Poseidon2 hash for a PAN record), with the
certificate's validity window. Each entry also holds the key's RSA modulus, so
the holder app can check a signature before proving; `checkRegistry` refuses an
entry whose modulus does not hash to its `keyHash` for its credential.

```bash
cd packages/issuer-registry
npm install
npm test
node build.mjs                             # rebuild registry.json after adding a certificate or key
node check.ts registry.json --production   # exit 1 on any test key or compromised key
```

- `productionRegistry()`: the keys in `registry.json`. Throws
  `TEST_KEY_IN_PRODUCTION` or `COMPROMISED_KEY` if an entry should not be
  there.
- `testRegistry(keys)`: ephemeral test keys, for tests and the local demo only;
  a key is for Aadhaar QRs unless it says `document: 'pan'`.
- `checkRegistry(registry)`, `findKey(registry, keyHash, document)`: a key
  trusted for one credential does not vouch for the other.

A build that ships a registry runs `check.ts --production`, which fails if any
test key is present (THREAT_MODEL test T1.5). Keys listed in
`security/compromised-keys.json`, such as the v1 demo key, are refused in every
registry.

| Key | Credential | Valid |
|---|---|---|
| `uidai-ds-4_2017-2020` | Aadhaar QR | 2017-06-08 to 2020-06-07 |
| `uidai-ds-05_2021-2024` | Aadhaar QR | 2021-02-26 to 2024-02-27 |
| `uidai-ds-05_2024-2026` | Aadhaar QR | 2024-02-21 to 2026-02-16 |
| `uidai-ds-06_2026-2029` | Aadhaar QR | 2026-02-03 to 2029-02-03 (signs current codes) |
| `digilocker-ds-2026-2029` | PAN record | 2026-02-13 to 2029-02-11 |

`registry.json` is generated by `build.mjs` from the UIDAI certificates in
`packages/secure-qr/certs` and DigiLocker's key in `packages/pan/keys.json`,
where each key's provenance is recorded. The 2021 UIDAI key's hash equals the
one Anon Aadhaar's SDK pins, an independent check of the key-hash computation.
DigiLocker's key is the one in the certificate every DigiLocker record carries;
the certificate itself is not committed, because its subject holds a person's
e-mail address (THREAT_MODEL, S11).

TypeScript, run directly by Node 22.18 or later (type stripping);
`npm run typecheck` runs `tsc`.
