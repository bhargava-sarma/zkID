# @zkid/issuer-registry

The issuer keys a zkID verifier trusts: UIDAI's Secure QR signing keys, each
stored as the key hash Anon Aadhaar's circuit outputs (`pubkeyHash`), with the
certificate's validity window. Each entry also holds the key's RSA modulus, so
the holder app can check a QR's signature before proving; `checkRegistry`
refuses an entry whose modulus does not hash to its `keyHash`.

```bash
cd packages/issuer-registry
npm install
npm test
node build.mjs                             # rebuild registry.json after adding a certificate
node check.ts registry.json --production   # exit 1 on any test key or compromised key
```

- `productionRegistry()`: the UIDAI keys in `registry.json`. Throws
  `TEST_KEY_IN_PRODUCTION` or `COMPROMISED_KEY` if an entry should not be
  there.
- `testRegistry(keys)`: ephemeral test keys, for tests and the local demo only.
- `checkRegistry(registry)`, `findKey(registry, keyHash)`.

A build that ships a registry runs `check.ts --production`, which fails if any
test key is present (THREAT_MODEL test T1.5). Keys listed in
`security/compromised-keys.json`, such as the v1 demo key, are refused in every
registry.

| Key | Valid |
|---|---|
| `uidai-ds-4_2017-2020` | 2017-06-08 to 2020-06-07 |
| `uidai-ds-05_2021-2024` | 2021-02-26 to 2024-02-27 |
| `uidai-ds-05_2024-2026` | 2024-02-21 to 2026-02-16 |
| `uidai-ds-06_2026-2029` | 2026-02-03 to 2029-02-03 (signs current codes) |

`registry.json` is generated by `build.mjs` from the certificates in
`packages/secure-qr/certs`, whose provenance is recorded there. The 2021 key's
hash equals the one Anon Aadhaar's SDK pins, an independent check of the
key-hash computation.

TypeScript, run directly by Node 22.18 or later (type stripping);
`npm run typecheck` runs `tsc`.
